# 00 原型库分类法与总索引

> 本目录是 `09-计谋原型库.md` 的扩展分库。主库管规则与计谋卡，本目录管"可查、可数、可溯源"的历史原型。
> 铁律不变：**无原型不写；战略 + 手法双层溯源；2–3 个原型拼接；不得自行编造。**

## 一、为什么要分层

三国同人写到中后期，主角每一次布局都要"像真的有人在历史上这么干过"。
一个扁平的原型清单会导致三个问题：查不到、记不住、用不准。
所以本库按**朝代 → 场景 → 机制 → 结果**四级切分，每朝代独立成卷，每卷至少 50 条。

## 三、条目格式

每卷正文统一用"两行式"，保证可扫读、可检索：

```markdown
1. **名称**（场景·机制·结果）目的：……。过程：……。结果：……。出处：《……》。风险：……
```

需要展开时，在卷末写"精讲卡"，使用主库的完整计谋卡模板：

```markdown
### 精讲-000 ｜ 名称
- 目的：
- 过程：
- 结果：
- 为何成立（当时的条件）：
- 失败风险：
- 出处：
- 三国/魏讽移植：
- 代价与后遗症：
```

## 四、来源与标注

| 级别 | 范围 | 用法 |
|---|---|---|
| A | 正史、兵书、政书（二十四史、《资治通鉴》《左传》《战国策》《孙子》《韩非子》《管子》） | 可直接用，标书名 |
| B | 世界制度史 | 只借机制，标国别与年代 |
| C | 演义、野史、笔记、传说 | 必须标"演义/野史"，不得当正史 |
| D | 近现代政治史 | 只取机制，守红线；不写种族主义、灭绝、美化独裁、酷刑细节 |

**不确定就写"待考"，不许编。**

## 五、收录标准（五条同时满足）

1. **真实发生过**：有史书或可靠史料落点。
2. **有目的**：能说清当事人想解决什么问题。
3. **有过程**：至少两步操作，不是一句结论。
4. **有结果**：成、败、反噬、半成，必须写清。
5. **有可移植机制**：能抽象成"借势/离间/合法性"等，供主角变形使用。

## 七、使用流程

1. **先定局**：这一卷主角要解决什么（活命、翻案、结盟、阻帝、立约）。
2. **再找原型**：按场景翻对应卷，筛 2–3 个机制匹配的条目。
3. **做变形**：写清"原型条件 → 本书条件"的差异，差异就是改造点。
4. **写失败可能**：每个原型都要写"如果被识破会怎样"。
5. **填计谋卡**：回到 `09-计谋原型库.md` 的模板，落成正文可用的卡。

## 八、维护规则

- 新条目只能追加，不改旧条目；如发现史实错误，标注"修订"并写原条目编号。
- 每卷保持在 50 条以上，新增按场景补位，不破坏配额。
- 演义/野史条目必须带 `[C]` 标记。
- 每季度复核一次：删掉重复、补上缺口、更新"待考"。
