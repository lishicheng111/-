# 日更章流水线

## 何时用

- 用户说"写第 N 章"
- 需要一次写多章存稿
- 卡文，需要先定位卡在哪

## 前置读取（缺一不可）

1. `project/<书名>/state/下一章钩子.md` — 上一章留下的钩子
2. `project/<书名>/state/人物当前状态.md` — 人物当下状态
3. `project/<书名>/arcs/剧情线状态机.md` — 当前在推哪条线
4. `project/<书名>/state/伏笔表.md` — 这一章该回收什么
5. `project/<书名>/chapters/章节目录.md` — 本章在原计划里的位置

## 流程

1. **定目标**：一句话写出本章"谁要什么、谁挡着、结果如何"。
2. **定章型**：推进章 / 冲突章 / 缓冲章。连续 3 章同型 → 强制换。
3. **写施工卡**（5 行）：承接 → 目标 → 阻碍 → 转折/兑现 → 钩子。
4. **写正文**：按 `wiki/craft/写作设计方法.md` §5–§7。
   - 2000–3500 字
   - 动作节拍替代"他说"
   - 不解释设定，用事件带出
5. **自检**：过 §10 十条清单，逐条打勾。不过关就改，不带病出稿。
6. **更新状态**（关键，不可省）：
   - `state/下一章钩子.md` 换成新钩子
   - `state/人物当前状态.md` 更新身体/情绪/已知信息/关系
   - `state/伏笔表.md` 标记已回收
   - `state/已用桥段.md` 登记用过的桥段
   - `state/已确立事实.md` 记录本章新立的规则
7. **落盘**：`output/drafts/<书名>/ch-<三位序号>.md`

## 卡文急救

| 症状 | 原因 | 处方 |
| --- | --- | --- |
| 不知道写什么 | 下一章目标缺失 | 回看 arc-status，补一个具体目标 |
| 写得很顺但很水 | 无阻碍 | 加一个具体的人或时间限制 |
| 主角不动 | 信息给得太顺 | 让信息有代价，或让配角拒绝 |
| 情绪起不来 | 压抑不足 | 补一段读者憋屈的具体场景 |

## 产出

章节正文 + 更新后的五个状态文件。
