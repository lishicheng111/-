# 钩子与爽点引擎

## 何时用

- 章末没有钩子，或钩子太虚
- 追读率下滑，需要诊断钩子
- 想批量储备桥段与钩子
- 每卷结束做一次"钩子账本"盘点

## 钩子设计

四型：信息钩 / 情绪钩 / 危机钩 / 承诺钩。
合格标准：
1. 指向**具体**即将发生的事件（不是"命运将改变"）。
2. 涉及一个**有名有姓**的人或一个已建立的规则。
3. 读者看完会想问一个具体问题。

强度阶梯：章末小钩（每章）→ 卷末中钩（30–50 章）→ 全书大钩（1–3 个）。
连续三章用同一型 → 换型。

## 爽点设计

公式：`压抑 → 反转 → 释放 → 余韵`。
检查：
- 压抑够不够（读者是否真的憋屈）
- 反转是否有前置信息（不能天降）
- 释放是否具体（动作、台词、结果）
- 余韵是否有人反应（旁人态度变化）

密度：每 3–5 章至少一个小爽点；每 30–50 章一个卷级高潮。

## 维护钩子库

- 新增 `wiki/hooks/<类型>-<名称>.md`：触发条件、写法、兑现方式、适用题材。
- 新增 `wiki/tropes/<类型>-<名称>.md`：核心机制、变体 3 种、禁忌。
- 在 `wiki/index.md` 登记。

## 产出

- 章末钩子 3 个备选（标注类型与强度）
- 或一份"钩子账本"：已埋未还 / 即将到期 / 重复类型
