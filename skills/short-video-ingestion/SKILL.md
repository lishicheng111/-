# 短视频博主素材通用拆解入库

## 何时用

- 用户指定某个抖音/B站博主，要求拆解其内容并入库
- 现有桥段库/知识点库/人设原型库不够用，需要从短视频取材
- 用户说"去拆一下这个博主""把这个博主的视频作为素材"

## 博主类型识别（第一步必做）

根据博主内容特征，先判定类型，再走对应拆解流程：

| 类型 | 识别特征 | 核心产出 | 入库位置 |
| --- | --- | --- | --- |
| **段子型** | 搞笑短剧、名场面、反转密集 | 结构模式 → 桥段零件 | `wiki/tropes/` + `wiki/craft/` |
| **知识型** | 讲心理学/社会学/商业理论，配场景演绎 | 知识点 → 伪获得感模板 | `wiki/craft/reader-gain/` + `wiki/analyses/` |
| **人设型** | 立鲜明人设、性格标签强 | 人设原型页 | `wiki/characters/` |
| **剧情型** | 连续剧式剧情、长线钩子 | 结构表 + 钩子表 | `wiki/tropes/` + `wiki/hooks/` |

> 多数博主混合多种类型。以**主要内容**判定主类型，其余类型的产出作为附加入库。

## 总流程（五步）

### 第一步：收集样本

1. 搜索博主：平台主页、飞瓜/新抖数据、B站收藏夹金句、二创剧本
2. 样本量：至少 8–15 个视频/知识点，越多越能发现共性
3. 每个样本记录：标题/一句话概括 + 关键内容（台词/反转点/知识点名）

### 第二步：判定类型并分流

按上表判定主类型。若为混合类型，**按主类型走完流程后**，对次要类型的产出单独走"抽取零件"步骤。

### 第三步：走对应类型的拆解流程

#### A. 段子型（参考 skit-ingestion 完整流程）

核心三问：预期是什么？实际发生了什么？为什么好笑？
→ 结构模式 → `wiki/tropes/<类型>-<名称>.md`（含变体、小说转化、禁忌）
→ 叙事技巧类放 `wiki/craft/`
详见 [skit-ingestion](../skit-ingestion/SKILL.md)

#### B. 知识型

核心四问：
1. 知识点的**学术理论名**是什么？（如旁观者效应、沉没成本）
2. 博主用**什么场景**演绎的？
3. 这个知识能解决小说里**什么类型的危机**？（围堵/操控/世界观）
4. 读者"听说过但没真正理解"吗？（是才有伪获得感）
→ 知识点清单（含理论名+场景+小说转化示例） → `wiki/craft/reader-gain/<名称>模板.md`
→ 综合分析页 → `wiki/analyses/<博主名>-知识点拆解.md`
参考：[鹏鹏有个想法-知识点拆解](wiki/analyses/鹏鹏有个想法-知识点拆解.md) + [鹏鹏式知识点植入模板](wiki/craft/reader-gain/鹏鹏式知识点植入模板.md)

#### C. 人设型

核心三问：
1. 这个角色的**读者默认预期**是什么？（约定俗成的设定包）
2. 博主用了什么**反差**打破默认预期？
3. 这个原型适合当**主角/配角/反派**？
→ 人设原型页 → `wiki/characters/原型-<名称>.md`（含默认预期、标志性符号、反差玩法、起点样本、小说用法、禁忌）
参考：[人设库总表](wiki/characters/_index.md) + [原型借力](wiki/craft/character/原型借力.md)

#### D. 剧情型

核心四问：
1. 每集的**钩子**怎么设计？（章末指向什么）
2. **爽点**怎么埋？（欲扬先抑？扮猪吃虎？）
3. **节奏**怎么控？（几集一个小高潮？）
4. 长线悬念怎么铺？
→ 结构表 + 钩子表 → `wiki/hooks/` + `wiki/tropes/`

### 第四步：写综合分析页

统一在 `wiki/analyses/<博主名>-<类型>拆解.md` 写完整分析，必含：
- 博主定位（内容形式、风格、受众门槛、数据规模）
- 样本库表格
- 核心机制/知识点/人设模式分析（每个带公式/示例 + 小说转化）
- 最值得抄的 3 条 + 最不该抄的 3 条
- 已入库的零件清单（带链接）

### 第五步：登记索引

必须更新以下文件，缺一不可：
- 对应零件目录的 `_index.md`（tropes / characters / hooks）
- `wiki/index.md`（拆书与分析区 + 对应零件区）
- `wiki/来源映射.md`（登记来源 + 产出）
- `wiki/log.md`（按日期倒序记录）

## 类型间联动规则

同一博主的产出可能同时落入多个目录。联动方式：

1. **知识点 + 段子**：知识点可作为段子的反转点来源（如用"对比效应"做段子反转）
2. **知识点 + 人设**：知识点可作为人物能力标签（如"条件反射→驯兽师之眼"）
3. **人设 + 段子**：人设原型可作为段子的固定主角（如"人机校花"演"宏大小用"段子）
4. **剧情 + 人设**：剧情钩子依赖人设反差（如"嘴硬打脸型"立"打脸"钩子）

在综合分析页的"联动"部分，写清本次产出和哪些已有零件可组合使用。

## 质量门槛（所有类型通用）

1. **必须给小说转化示例**，不能只停留在视频内容本身
2. **变体/反差不能只是换皮**，要换核心变量（换目标、换场景、换关系、换认知层级）
3. **必须标注"不该抄的毛病"**，避免生搬硬套（如梗太硬核、抽象无逻辑、知识点硬塞百科）
4. **知识点必须真实可查**，原理错了会破坏读者信任
5. **人设必须有具体记忆锚点**（一个动作、一件道具、一句口头禅），不能只有标签

## 产出示例

```text
《博主名》拆解
- 类型：知识型（主）+ 段子型（副）
- 样本数：15 个知识点 + 3 个段子
- 主产出：wiki/craft/reader-gain/鹏鹏式知识点植入模板.md
- 附产出：wiki/tropes/宏大小用.md（段子型联动）
- 最值得抄：知识点作为破局器（成本低、爽感强）
- 最不该抄：知识点硬塞百科（打断节奏、变成科普文）
- 联动：知识点可作为"嘴硬打脸型"人设的能力标签
```
