# 数据复盘

## 何时用

- 新书期每周一次
- 上架首月每周一次
- 均订停滞、追读下滑
- 用户提供后台截图或数据

## 流程

1. **收集**：追读率、收藏、推荐票、月票、均订、追订比、完读率（有多少填多少，缺的标"无数据"）。
2. **对照基线**（新人参考，非绝对）：
   - 前 3 章追读 ≥ 50% 算健康
   - 首月均订 ≥ 500 算及格
   - 完读率 < 60% → 章节偏水
3. **定位**：按 `wiki/craft/写作设计方法.md` §9 的诊断表匹配症状。
4. **归因排序**：最多列 3 个原因，按影响排序。禁止一次列 10 条。
5. **处方**：只改一个变量，给出未来 5 章的调整方案与观察指标。
6. **记录**：`output/reports/复盘-YYYY-MM-DD.md`，并在 `memory/worklog/` 留一条摘要。

## 归因纪律

- 数据差不等于书差，可能是曝光问题（推荐位、更新时段）。
- 不用"读者不懂欣赏"解释任何数据。
- 不为了数据改人设底线；改节奏，不改灵魂。

## 产出

一份复盘报告：现状 → 诊断 → 单变量方案 → 观察指标 → 下次复盘时间。
