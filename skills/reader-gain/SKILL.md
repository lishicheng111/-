# 伪获得感设计

## 何时用

- 纯爽文写久了，读者追读率下降（爽感钝化）
- 想提升作品厚度和留存
- 想缓解读者"看小说浪费时间"的负罪感
- 主角有某个专业/知识背景，想利用起来

## 核心原则

**知识是解决问题的武器，不是装饰。** 读者要的是"我懂了"的瞬间，不是百科全书。

## 流程

### 第一步：选一个知识单元

每 3–5 章植入一个知识单元，选知识遵循：

- 读者"听说过但不懂"的（心理学效应、物理常识、历史冷知识、生活技巧）
- 能和当前剧情的危机绑定的
- 真实可查的（不能瞎编）
- 1–2 句话能解释清楚的

知识池示例（按题材）：
- 都市：心理学效应、法律条文、金融常识、职场规则
- 玄幻：中医/草药知识、天文星象、历史典故
- 悬疑：法医知识、犯罪心理学、逻辑推理
- 历史：当时的生活习俗、器物、制度
- 科幻：基础物理、生物学、计算机原理

### 第二步：选植入方式

四种方式选一种（参考 [伪获得感](wiki/craft/reader-gain/伪获得感.md)）：

1. **知识即武器**：主角用知识解决危机
2. **知识即钩子**：用反常识知识制造悬念
3. **知识即世界观**：知识融入设定
4. **知识即身份标签**：知识成为主角的社交货币

### 第三步：按四幕结构写

```text
问题提出 → 科学转译 → 实践验证 → 认知升级
```

1. **问题提出**：主角遇到看似无解的危机（1 段）
2. **科学转译**：主角想到某个知识，用 1–2 句解释原理（读者"我懂了"）
3. **实践验证**：主角用知识解决危机（读者"还能这么用"）
4. **认知升级**：危机解决后，对这个知识有新理解（读者"又学到一层"）

### 第四步：自检（5 条）

1. 知识和当前危机绑定了吗？还是硬塞的？→ 硬塞的删掉
2. 知识解释 ≤ 2 句话？→ 超了就砍
3. 读者能感知这个知识吗？（听说过但不懂）→ 太专业的换一个
4. 知识是真实的吗？（能查到）→ 不确定的不写
5. 知识有没有盖过情绪流？→ 知识是辅助，情绪流才是主线

### 第五步：知识池维护

- 写过的知识记入 `wiki/reader-gain/知识池.md`（待建），标注用过的章号，避免重复
- 每写完一卷复盘：哪些知识单元读者反应好（评论区有讨论），哪些被跳过了

## 硬指标

- 每 3–5 章最多一个知识单元，不密塞
- 每个知识单元的知识解释 ≤ 2 句话
- 知识必须和当前危机强绑定
- 知识必须真实可查
- 知识不能盖过情绪流（情绪流是主线，伪获得感是辅助）

## 产出

- 每卷的知识单元清单（知识内容 + 植入章号 + 植入方式）
- 知识池（写过的知识点 + 章号，避免重复）
